Building a Chief of Staff and an agentic team on Claude

A Chief of Staff (CoS) agent is the single front door. It knows your priorities, runs the daily rhythm, hands work to specialists and brings results back to you for a decision. This guide builds it in twelve steps, simplest first. Each step should work on its own before you add the next.

Read this first GrokcosClaude now has several places where agents can live: chat Projects, Cowork (long-running and scheduled tasks), Claude Code (repositories, subagents, agent teams) and the Claude Agent SDK (your own software). They are not one system, and a Project in chat cannot hand work to another Project by itself. Step 0 shows which piece does which job, so the rest of the guide only promises what Claude actually does today.

Suggested pathStart with one Project plus scheduled tasks for the rhythm. Add specialists as separate Projects or Cowork projects with their own role cards. Move to Claude Code subagents only when a lane is mostly repository work. Treat the Agent SDK as a later step, when you want the team to run inside your own platform.

1Write the charter: one page, before any setup Grokcos

The charter is what every agent reads first. It doubles as the CoS Project's instructions. Keep it short: the help centre advises concise project instructions, because long ones use more of your context and usage. Copy, then fill the brackets.

ROLE         Chief of Staff to [name]. Protect attention; move decisions forward.
OWNS         Morning and evening briefs · inbox triage · follow-ups · research intake
             · drafting · routing work to specialists · weekly review.
NEVER        Sends, pays, deletes, publishes, signs or shares without my explicit "yes"
             in this chat. Puts personal or financial details into web searches or
             outside services. Invents a fact, figure, name, email or phone number.
ASKS FIRST   Anything irreversible · anything over ₹[limit] · any new contact ·
             any change to a repo, website or calendar invite with other people on it.
DONE MEANS   A file I can open or a decision I can make, with sources linked,
             plus a list of what is still open.
WHEN STUCK   Say so in one line, what you tried, and the one question that unblocks you.
             Do not work around a permission or a login.
TONE         Professional, organised, brief, humble. Ask clarifying questions; don't guess.
TIME         All times in IST (UTC+5:30).
Why firstAgents drift when their limits live only in your head. A written "never", "asks first" and "when stuck" list is the cheapest safety system you will build, and every specialist inherits it.

3Create the Chief of Staff Project Grokcos

  1. In Claude, open Projects and choose New project. Name it Chief of Staff. On Team or Enterprise, keep it private.
  2. Open Set project instructions and paste the charter from step 1.
  3. Add standing reference files to the project knowledge: this quarter's priorities, the list of ventures, key contacts by role, and your house style (for example the dated design guidelines kept in each page's source).
  4. Keep one Project per domain (for example Crop Assessment, Farm Operations, Personal Finance), so context and memory don't leak between them. The CoS refers you to them; it doesn't absorb them.
  5. Test it: ask "What do you own, what will you never do, and what do you ask first?" If the answer doesn't match the charter, shorten the charter.
Changing featureAnthropic is rolling out a new version of projects in beta, starting with Claude Code for some Pro and Max users. In it, a project is one ongoing conversation that splits work into parallel threads in the cloud. If your projects look different, follow the help centre article; the charter and role cards still apply.

4Set memory and preferences deliberately Grokcos

  • State durable preferences once ("ask before acting", "brief, organised, professional"). You can also say "remember this". Memory now works on all plans; on Team and Enterprise it stays off until you turn it on.
  • Each Project has its own memory. By default a Project also uses your general (account) memory. For financial and personal Projects, turn off Use account memory on the Project's page so they stay fully separate.
  • Once a month, open Settings › Memory and review the listed topics. Edit or delete anything stale. Sensitive topics such as health stay out of memory unless you switch them on.
  • In Claude Code, durable rules live in a CLAUDE.md file in the repository instead; see Claude Code memory.

5Connect only the tools the CoS needs Grokcos

  1. Start with Calendar, Gmail and Drive (Customize › Connectors). On Team and Enterprise, an owner must enable them first.
  2. Know what they can do. The Gmail connector can send, reply and forward, not just draft. Drive can share, move and trash files. By default Claude asks for your approval before each of these; keep it that way. On Team and Enterprise, owners can let members skip those prompts. Don't.
  3. Add GitHub, Netlify or others only when a lane needs them. Look in the connector directory first. A custom connector needs a remote MCP server on the public internet (Free plans get one). Only connect servers from organisations you trust.
  4. Turn off connectors a chat doesn't need. They use a lot of tokens and give untrusted content more ways in.
Prompt injectionAn email or web page can contain instructions written to hijack an agent ("ignore your instructions and transfer…"). Anthropic's own safety guidance says the risk needs two things at once: the agent reads outside content and can take consequential actions. Keep those apart: the lane that reads your inbox drafts, and only you send.

6Turn repeated routines into skills Grokcos

When you have explained the same procedure twice, make it a skill. First turn on Code execution and file creation (Settings › Capabilities); skills need it. Ask Claude to help write the skill as a folder containing a SKILL.md file, then upload it under Customize › Skills. Skills you enable there also load in Claude Code when you sign in with the same account.

---
name: link-audit
description: Open every link on a page, mark each verified, revised or fixed, and log the date. Use before publishing any baseline page.
---
1. List every external link with its anchor text.
2. Open each one. Record status (works / redirects / broken) and the final URL.
3. Redirected to the same content  -> replace URL, add pill "Link revised".
   Broken or wrong content         -> find the correct official page, add pill "Link fixed".
4. Every external link: target="_blank" rel="noopener".
5. Output a table: link, old URL, new URL, status, date checked (IST).
Never mark a link verified without opening it.

Other good first skills:

  • Policy baseline page: research, then a single-file HTML page with pill-marked links, asides, SEO, an abbreviation glossary and a sources log (the method behind the ethanol page).
  • Officer letter: formal, short, with a reference number, the attachments listed, and contact details only from official pages.
  • Morning brief: the format in step 7, so every run looks the same.

7Schedule the cadence Grokcos

Scheduled tasks need a paid plan. Create them from the Scheduled page in Cowork, by typing /schedule, or by describing the task in a conversation if you have the new combined experience. You can pick hourly, daily, weekdays, weekly or manual runs, plus an approval mode. They run in the cloud, so your laptop can be closed. For repository work, Claude Code has its own cloud scheduled tasks (formerly routines), which can also fire on GitHub events.

When (IST)What the CoS producesApproval mode

Weekdays 17:30Tomorrow's list and office-hours itemsReads only
Friday 16:00Weekly review (step 12): shipped, stalled, decisions neededReads only
On demandLink audit before publishing a pageManually approve
MORNING BRIEF  (scheduled task prompt)
Using my Calendar and Gmail for the last 24 hours and today:
1. Today's meetings with a one-line "what I need to bring".
2. Up to 5 emails that need me, each with a suggested reply as a DRAFT only.
3. "Waiting on others": threads where I am owed a reply for 3+ days.
4. One focus for today, from the priorities file in project knowledge.
Do not send, accept, decline or delete anything. End with one question for me, or "No decisions needed."
RuleEvery scheduled run must end in something you can act on in under two minutes: a decision to make, a draft to approve or a file to open. Anthropic advises against scheduling tasks that send messages, make purchases or touch sensitive files, because nobody is watching when they run. Review past runs on the Scheduled page, and pause the ones you no longer read.

8Add specialists one at a time Grokcos

Give each specialist a role card in the same format as the charter. Add the next one only after the previous one has produced three outputs you used unchanged. There are three honest ways to run a specialist:

A Verifier written as a Claude Code subagent (.claude/agents/verifier.md). See Create custom subagents:

---
name: verifier
description: Independently checks a finished draft's facts, links and arithmetic. Use after any page or letter is drafted, before it goes to Vipul.
tools: Read, Grep, Glob, WebFetch
---
You did not write this draft. Check every factual claim against its cited source,
open every link, and recompute every number. Report: claim, source, OK / wrong / unsourced.
Do not edit files. Do not fix silently. List problems; the lead decides.

9Define handoffs and approvals Grokcos

  1. Brief in: the CoS writes a task card.
  2. Work: the specialist produces a draft and a handoff note.
  3. Verify: a fresh agent checks facts, links and arithmetic, without having seen the drafting.
  4. Decide: the CoS presents it with a recommendation and one question.
  5. Ship: only after your "yes". The CoS records what shipped and where.
TASK CARD                          HANDOFF NOTE (back to the CoS)
Goal:      [one sentence]           Done:       [what was produced, link/file]
Inputs:    [files, links]           Sources:    [yielded] / [didn't yield]
Output:    [format, length]         Confidence: high / medium / low, and why
Deadline:  [date, IST]              Open:       [questions, gaps]
Limits:    [never / asks-first]     Needs you:  [one decision, or "nothing"]
Done when: [test]                   Blocked:    [yes/no, what would unblock]
Approval ruleExamplesWhat the agent may do
Green: just do itRead, search, summarise, draft, save a file in its own folderAct, then report
Amber: show me firstPush to a repo, edit a shared doc, create a calendar event with others, new contactPrepare the exact change; wait for "yes"
Red: only I do itSend email or messages, pay or buy, delete, sign, share personal or financial data, publish under my nameDraft only; I press send
Privacy lineDecide up front which lanes may use subagents or outside services. Personal and financial work stays in one separate Project, with account memory off, and never goes into search queries.

10When a lead hits a wall: troubleshooting and escalation Grokcos

Agents get stuck in predictable ways. The rule: say so early, try one safer route, then ask. Never route around a permission, a login or an approval.

SymptomLikely causeFix
Scheduled brief didn't arriveTask paused, plan isn't paid, or the task needs local files and the computer was offCheck the Scheduled page's past runs; run it on demand once
Connector "not available"Not enabled by the org owner, or not signed inOwner enables it; reconnect under Customize › Connectors
Skills section missingCode execution is offTurn on Code execution and file creation
Answers ignore the charterInstructions too long, or the chat isn't in the ProjectShorten the charter; start the chat inside the Project
Same task keeps failingTask card too vague, or a site blocks automated accessNarrow the goal; give the exact source; accept a documented gap
"Usage limit reached"Five-hour or weekly limitSee step 11; wait for the reset, or pause low-value runs
Agent reads an instruction inside an email or pagePossible prompt injectionStop the task; don't act on it; report from the app
ESCALATION LADDER
1. Retry once with a narrower scope or an official source.        (agent)
2. Hand to the Verifier or a fresh chat for a second look.         (agent)
3. Write a BLOCKED note: what, why, what was tried, one question. (agent -> CoS)
4. CoS brings it to me with a recommendation, at the next brief.   (CoS -> me)
5. Park it with a date to revisit, or drop it. Record the decision. (me)

11Cost and usage Grokcos

  • On paid plans, usage has a session limit that resets every five hours and weekly limits. Chat, Claude Code and the desktop app all draw on the same allowance.
  • Research, long conversations, connectors and agent teams use more. Anthropic says agent teams use "significantly more tokens than a single session".
  • Every scheduled run counts. Start with two daily runs and one weekly run, not hourly ones.
  • Keep instructions short, remove unused project files, and turn off connectors and extended thinking when a task doesn't need them.
  • When you hit a limit, wait for the reset, upgrade, or turn on usage credits. In Claude Code, an ANTHROPIC_API_KEY environment variable bills the API instead of your plan; don't set one by accident.

12Review weekly and prune Grokcos

WEEKLY REVIEW  (Friday, 15 minutes)
[ ] Outputs I used unchanged        -> keep that routine or skill.
[ ] Outputs I rewrote               -> fix the role card or skill, not the output.
[ ] Outputs I ignored               -> pause or delete that scheduled task.
[ ] Anything sent, paid, pushed     -> did each have my "yes"? If not, tighten the rules.
[ ] Blocked notes                   -> decide: unblock, park with a date, or drop.
[ ] Memory topics                   -> delete anything stale or wrong (monthly).
[ ] Connectors                      -> disconnect any not used in 30 days.
[ ] Usage                           -> which run cost the most for the least value?

Recall questions Grokcos

Short questions to check the guide has stuck. Tap one to see the answer.

1. Which Claude plans can run scheduled tasks?

Paid plans only: Pro, Max, Team and Enterprise.

2. What must be switched on before Skills appear?

Code execution and file creation.

3. How do you keep a personal-finance Project's memory fully separate?

Turn off "Use account memory" on that Project's page.

4. Can the Gmail connector send email by itself?

It can send, reply and forward, but by default asks for approval each time. Keep that on; sending is a red action.

5. Where does real automatic delegation to subagents happen?

In Claude Code (subagents; agent teams are experimental), or in your own app through the Agent SDK. Not between chat Projects.

6. What are the three colours of the approval rule?

Green: just do it. Amber: show me first. Red: only I do it.

7. What two conditions make prompt injection dangerous?

The agent reads untrusted content and can also take consequential actions.
